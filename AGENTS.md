# Aturan Kerja Tookthel

Repo ini dikerjakan berdua oleh **Bintang** ([@bintangfabian](https://github.com/bintangfabian)) dan **Haikal** ([@HaikalFaruq](https://github.com/HaikalFaruq)), sering dengan bantuan AI agent. Aturan di bawah berlaku untuk kita berdua dan untuk agent apa pun yang dipakai.

## 1. Tanpa atribusi AI

Commit, PR, issue, dan komentar tercatat atas nama orang yang menjalankannya. Jangan tulis atribusi AI dalam bentuk apa pun:

- Trailer seperti `Co-Authored-By: Claude <noreply@anthropic.com>`, `Claude-Session: …`, `Assisted-by: …`, dan trailer sejenis dari agent lain (Codex, Copilot, Cursor, Gemini, Aider, Devin, Jules, Amp, Warp, dan seterusnya).
- Footer seperti `🤖 Generated with Claude Code` atau `Generated by Copilot`, serta link sesi agent.
- Agent atau bot AI sebagai author atau committer, misalnya `claude[bot]`, `Copilot`, `Cursor Agent`, `devin-ai-integration[bot]`, atau nama berakhiran `(aider)`. Commit selalu memakai identitas git kamu sendiri.

Kalau agent kamu menambahkan atribusi otomatis, matikan di setting-nya. Untuk Claude Code sudah dimatikan lewat `.claude/settings.json` di repo ini.

Aturan ini dicek berlapis, jadi pelanggaran berhenti sebelum masuk `main`:

| Lapis | Yang dicek | Kapan |
| --- | --- | --- |
| `.githooks/commit-msg` | Pesan commit | Setiap `git commit` |
| `.githooks/pre-push` | Author, committer, dan pesan semua commit yang di-push | Setiap `git push` |
| Workflow `No AI attribution` | Sama seperti pre-push, plus judul dan deskripsi PR | Setiap PR dan push ke `main` |

Hook aktif otomatis setelah `npm install` (script `prepare`). Kalau belum, aktifkan sekali per clone:

```sh
git config core.hooksPath .githooks
```

Kalau ditolak, perbaiki commit-nya. Jangan lewati hook dengan `--no-verify`, karena CI tetap menolaknya.

| Kasus | Perintah |
| --- | --- |
| Pesan commit terakhir | `git commit --amend`, lalu hapus atribusinya |
| Author commit terakhir | `git commit --amend --reset-author --no-edit` |
| Commit yang lebih lama | `git rebase -i origin/main`, tandai `reword` atau `edit`, lalu `git push --force-with-lease` ke branch fitur kamu, tidak pernah ke `main` |

Semua pola ada di `scripts/check-no-ai.sh` dan contohnya di `scripts/test-check-no-ai.sh`. Kalau ada agent baru yang lolos, tambahkan pola dan contohnya lewat PR.

## 2. Pasangan jadi co-author

Setiap commit menyertakan pasangan sebagai co-author, supaya begitu PR-nya di-merge kita berdua dapat achievement **Pair Extraordinaire**.

| Yang commit | Trailer di akhir pesan commit |
| --- | --- |
| Haikal | `Co-authored-by: Bintang Fabian Putra <47806878+bintangfabian@users.noreply.github.com>` |
| Bintang | `Co-authored-by: Muhammad Haikal Faruq <50310521+HaikalFaruq@users.noreply.github.com>` |

- Taruh trailer di baris paling akhir, dipisah satu baris kosong dari isi pesan.
- Pakai email noreply di atas. Email ini pasti terhubung ke akun GitHub masing-masing, jadi co-author-nya terhitung.
- Merge PR pakai **Create a merge commit** (`gh pr merge --merge`), jangan squash. Satu-satunya PR yang terbukti memberi Pair Extraordinaire (kalku-app#3, 2025) memakai merge commit, sedangkan PR #3, #6, #7, #9–#13, dan #15 yang di-squash tidak memberi badge ke siapa pun.

## 3. Pesan commit dan PR harus bisa dilanjutkan

Siapa pun yang baca harus langsung paham apa yang berubah dan bisa lanjut dari situ.

**Commit:** format Conventional Commits dalam Bahasa Indonesia (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`). Judul maksimal 72 karakter. Isi pesan menjelaskan apa yang berubah dan kenapa.

**PR:** deskripsi memakai bagian berikut.

```markdown
## Apa yang berubah
## Kenapa
## Sudah dicek
## Selanjutnya
```

Bagian **Selanjutnya** berisi langkah berikutnya, hal yang belum beres, atau keputusan yang perlu diambil pasangan. Jangan dikosongkan.

## 4. Alur kerja

Issue → branch (`feat/…`, `fix/…`, `docs/…`) → PR → merge, satu PR untuk satu topik.

Jangan push langsung ke `main`. Co-author baru terhitung untuk achievement kalau commit-nya masuk lewat PR yang di-merge.

Setiap mulai sesi, termasuk sesi AI agent:

1. Sinkron dulu: `git switch main && git pull`.
2. Pastikan hook aktif: `git config core.hooksPath` harus mengeluarkan `.githooks` (bagian 1).
3. Baca roadmap beserta komentarnya: `gh issue view 8 --comments`. Komentar terakhir berisi langkah berikutnya dari pasangan.
4. Ambil satu item yang belum dicentang, lalu kerjakan lewat alur di atas.
5. Setelah PR di-merge, centang itemnya di #8.

## 5. Perintah

| Perintah | Fungsi |
| --- | --- |
| `npm run dev` | Server development |
| `npm run typecheck` | Cek tipe TypeScript |
| `npm run lint` | Lint (oxlint): aturan React hooks, aksesibilitas, TypeScript. Warning juga dianggap gagal |
| `npm test` | Unit test (Vitest) |
| `npm run test:e2e` | E2E di browser (Playwright, build production dulu otomatis) |
| `npm run build` | Build production + PWA |
| `scripts/check-no-ai.sh --revs origin/main..HEAD` | Cek atribusi AI di commit yang belum masuk `main` |
| `scripts/test-check-no-ai.sh` | Uji pola cek atribusi AI, wajib lolos setelah polanya diubah |

Pertama kali menjalankan E2E di mesin baru: `npx playwright install --only-shell chromium`.

Sebelum push, pastikan `npm run lint`, `npm test`, dan `npm run test:e2e` lolos. Perilaku baru wajib disertai test: logika di unit test, alur pengguna di E2E. CI di GitHub Actions menjalankan semuanya di setiap PR (workflow `CI` dan `No AI attribution`).

## 6. Arsitektur

```
src/
  domain/    logika murni: tipe tagihan, hitung, validasi langkah, teks bagikan, ekspresi ilustrasi
  state/     reducer, penyimpanan localStorage, hook useBill
  lib/       utilitas umum: format rupiah, id
  ui/        komponen dasar tanpa logika bisnis (Button, Sheet, input, ilustrasi)
  features/  satu folder per langkah: people, items, charges, result
  app/       komposisi: App, header, navigasi langkah, bar bawah
e2e/         skenario Playwright
scripts/     cek atribusi AI beserta test-nya
.githooks/   hook commit-msg dan pre-push
```

| Layer | Boleh import |
| --- | --- |
| `app` | semua layer |
| `features` | `ui`, `state`, `domain`, `lib` |
| `state` | `domain`, `lib` |
| `ui` | `lib` |
| `domain` | `lib` |
| `lib` | (tidak ada) |

- `domain` dan `lib` tidak boleh import React, supaya bisa dites dengan unit test biasa.
- `ui` tidak tahu apa-apa soal tagihan. Kalau komponen butuh data tagihan, tempatnya di `features`.
- Logika baru (hitungan, validasi, format) masuk ke `domain` atau `lib` beserta unit test-nya. Komponen cukup menampilkan data dan memanggil `dispatch`.
- Test ditaruh di sebelah filenya: `calculate.ts` → `calculate.test.ts`.

## 7. Desain

Karakter tampilan Tookthel dipertahankan: kartu bento warna-warni, ilustrasi berwajah, aksen serif miring di judul, logo struk lime tersenyum di kotak gelap, dan confetti. Desainnya pernah diganti total di #18 lalu dikembalikan di #20, jadi:

- Yang boleh langsung dikerjakan: memoles detail seperti kontras, jarak, teks yang terpotong, dan konsistensi gerak.
- Mengganti elemen identitas (warna, logo, ilustrasi, font, gaya kartu) harus ditanyakan ke pasangan dulu, dengan screenshot sebelum dan sesudah.
- Cek tampilan di lebar 320 px dan 390 px, mode terang dan gelap.
- Ilustrasi ada di `src/ui/Illustrations.tsx`. Ekspresi wajah struk dipilih oleh `billMood` di `src/domain/mood.ts`.
- Logo ada di `src/ui/Logo.tsx` dan dipakai di header serta kepala struk. Bentuknya sama dengan `public/logo.svg`, sumber favicon dan ikon PWA (`npm run icons`). Kalau logonya berubah, ubah keduanya.
